# 故事书数据与校对记录

“故事书号码快查”使用用户提供的《阿格莫尼亚故事书》中文扫描 PDF。网页保存的是对应段落的扫描裁图，保留中文正文、数字、图标、检定、选项、图表和谜题；不使用未经逐字校对的 OCR 正文。

## 覆盖范围

- 原 PDF 共 72 页：第 1–2 页为封面及说明，第 3–71 页包含故事，第 72 页为封底。
- 共 **896 个实际出现的故事编号**，范围为 `001`–`999`，并非连续编号。缺号不会自动补齐或用邻号替代。
- 共 **973 张段落图片**，其中 77 条故事有跨栏或跨页续文，按原书的阅读顺序排列。
- 数据中的 `pages` 是原 PDF 的一基页序。抽查可见的印刷页码与 PDF 页序相符；网页统一显示“PDF 第 N 页”，避免混淆不同扫描版本。
- 页面只按输入的精确编号加载对应段落，不列出邻近故事标题或内容。

## 数据来源与可复现性

原始 PDF SHA-256：

```text
4e85114f56a5bbcf4adfa5117b9c2aa91f7a48b99f88ed50bc15a64ed576e439
```

`docs/storybook-index.json` 保存人工核准的标题编号、栏位和裁剪坐标，以及每页内嵌 JPEG 的 SHA-256。坐标以 JPEG 原图像素为单位；不依赖 PDF 页面的横竖尺寸或外加白边。原 PDF 及整页 JPEG 不随网站提交。

`assets/story-data.js` 提供编号到段落图片、尺寸及 PDF 页序的映射；`assets/stories/` 只保存对应的段落 WebP。重建脚本验证 PDF 和缓存 JPEG 的校验值，拒绝把本版坐标用于另一份扫描。

重建需要 Python 3、Pillow、NumPy 及 Poppler 的 `pdfimages`：

```sh
python3 scripts/extract_storybook.py '/path/to/阿格莫尼亚故事书.pdf' --work /tmp/agemonia-story-rebuild
```

只生成指定校对样本，可添加 `--only 001,004,026,560,872,999`。这种模式不会覆盖正式数据文件。完整生成会清理不再被数据引用的旧段落图片。

## 校对方法与重要例外

1. 从 PDF 提取原始内嵌 JPEG，通过蓝色标题条定位候选标题。
2. 将全部候选编号制成联系表，由并行审阅逐一核对。OCR 仅用于辅助查错，其输出不作为最终正文或编号依据。
3. 合并被白字或色偏分割的同一标题；补回低阈值复扫发现的 `257`。人工确认包括 `501`、`641`–`648`、`988`、`996` 在内的实际缺号。
4. 按页、栏、标题的顺序分割正文；无标题的下一栏仍可属于前一段落。`004` 跨栏，`026` 跨页；`560` 和 `872` 均保留整栏谜题续文。
5. 单独标定 7 个带扫描边框的页面顶部。排除 `195`、`507`、`687` 后方只有边缘编号装饰的空白栏顶。短续文不按高度删除：`461`、`548`、`675`、`795` 的短片均为真实正文。
6. `999` 在最后的规则框后结束，不包含下方制作署名。署名属于原书说明，本工具只展示指定故事段落。
7. 独立视觉抽查 `001`、`004`、`009`、`026`、`040`、`434`、`521`、`540`、`560`、`613`、`844`、`872`、`911`、`933`、`987`、`998`、`999`，检查标题、跨栏/跨页顺序、谜题完整性与相邻内容边界；另检查所有短续片。

本数据是对指定中文扫描版的段落整理，不对原书译文或印刷勘误作改写。更换来源或修正坐标后，需要重新执行结构验证和对应段落的视觉检查。

## 发布验证

- `node scripts/check_storybook.mjs` 检查所有编号、图片引用、已核准的真实缺号、跨栏/跨页样本及页框例外。
- 全部 973 张 WebP 已解码，尺寸与索引一致；HTML 和样式表的本地文件引用无缺失。
- 浏览器检查涵盖短号与全角数字、无效与不存在号码、跨页阅读、深链默认收起、浏览器返回、图片失败重试、原文放大、320/390 像素手机宽度、索引加载失败及禁用脚本回退。
